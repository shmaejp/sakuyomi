# サーバー側の土台に Supabase を使う

汎用部分は作り込まない方針のため、データベース・ファイル保存・認証・サーバー関数がひとまとめになった Supabase を使う。記録・観察・判断・作業・圃場・作目・農場メンバーは、互いに参照し合う（根拠が観察を指す、判断者がメンバーを指す、など）。これはリレーショナルな Postgres が素直に表せる形であり、ADR 0001 の「派生物を作り直す」も SQL で扱いやすい。ドキュメント型の Firebase（Firestore）や、AWS などで自前に組む案は、この参照関係の扱いと作り込みの量の点で採らない。他の農場のデータを見えなくする仕組みは、Supabase の RLS に頼る。
